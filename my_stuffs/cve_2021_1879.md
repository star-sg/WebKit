# WebKit QuickTimePluginReplacement Use-after-free

## Affected Version

tag: releases/Apple/Safari-15.1-macOS-12.0.1

## Description of the vulnerability

Free objects are only handled if it was allocated inside heap zones mangaged by GarbageCollector. By then, GC craetes some write-barriers placed where the pointer is accessed to write. It is a small piece of instrumentation that executes after every write to an object — that tells the GC about writes to old objects. However, that instrumentation code is not existed in binding part. Therefore, if we get a pointer when we stay in a binding api, GC will never know that pointer has been referenced, which results in an Use-after-free.

## Technical Details


### The Vulnerability

Class QuickTimePluginReplacement has a raw pointer `m_scriptObject` point to an internal JSObject:

```c
class QuickTimePluginReplacement final : public PluginReplacement {
private:
    ...
    JSC::JSObject* m_scriptObject { nullptr };
};
```

At the beginning, this object was retrieved from JavaScript context by calling `get` method:

```c
value = replacement.get(lexicalGlobalObject, JSC::Identifier::fromString(vm, "scriptObject"));
    if (!scope.exception() && !value.isUndefinedOrNull()) {
        m_scriptObject = value.toObject(lexicalGlobalObject);
        scope.assertNoException();
    }
```

This is actually a function table in JS script ( `Source/WebCore/Modules/plugins/QuickTimePluginReplacement.js` ). After rendering, we can call to some of this api by communicating with embeded tag.

```html
<embed id="worker" src="data:video/mp4;"></embed>
```

For example, when we call `worker.GetURL()`, codeflow will go to this C backend code, and find "GetURL" properety from `m_scriptObject`:

```c
JSC_DEFINE_CUSTOM_GETTER(pluginElementPropertyGetter, (JSGlobalObject* lexicalGlobalObject, EncodedJSValue thisValue, PropertyName propertyName))
{
    VM& vm = lexicalGlobalObject->vm();
    auto scope = DECLARE_THROW_SCOPE(vm);

    JSHTMLElement* thisObject = jsDynamicCast<JSHTMLElement*>(vm, JSValue::decode(thisValue));
    if (!thisObject)
        return throwVMTypeError(lexicalGlobalObject, scope);
    JSObject* scriptObject = pluginScriptObject(lexicalGlobalObject, thisObject);
    if (!scriptObject)
        return JSValue::encode(jsUndefined());

    return JSValue::encode(scriptObject->get(lexicalGlobalObject, propertyName));
}
```

When we refresh an iframe containing this embeded tag, the original scriptObject, which was allocated by JS engine from the JS script above, will be discarded and collected by GarbageCollector in next wave of collection. However, because `m_scriptObject` is not handled by GarbageCollector, then now we are able to access to a freed JSObject via worker.
